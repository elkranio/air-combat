# Terrain radar — union and query optimization (WIP)

Base `a639573`. CL06B and its two CL06C orientation trials are unchanged. Runtime-only change: no scene, prefab, model, material, lighting, flight, collision or radar-contact changes. The existing radar and terrain proximity warning now share a cached union of the stationary rock cross-sections. No external geometry package.

## Implementation

- Keep each marked rock as a closed solid, with world bounds cached at enable. Canonicalize shared-edge interpolation, reuse slice scratch buffers and sort computed intersections without capturing lambdas. During changing altitude, use the previous per-rock rendering path, with a bounds rejection before slicing. Warning uses the same exact-altitude nearby-rock fallback immediately, not a delayed sample.
- After the radar has observed a stable height for 0.25 seconds, build the union at that height (same 0.001-unit cache tolerance as the previous slicer). A scan sweep splits at vertices and inter-rock edge crossings, uses parity within a rock and OR across rocks, and merges consecutive bands with identical edges. Draw only the union fill and the real external/hole boundaries, not the internal overlap outlines. Double precision for sweep math, small numeric tolerances; no convex hull or raster grid. If input is inconsistent, fall back to individual culled sections and log once per attempted height/revision. The cache is invalidated by scene/altitude changes and obstacle enable/disable. Marked rocks must remain stationary while enabled, as before.
- Radar rejects distant primitives before projection and bypasses 48-plane clipping for geometry fully inside the inscribed circle. Warning checks the union boundary when available, with cheap segment bounds rejection before closest-point math; the original 22.5-unit threshold, arc and chime are unchanged. Inside a solid, the warning is now relative to its union boundary, not buried rock seams. This is still only a proximity warning, not a collision solver.
- Radar update cadence is unchanged (per frame). Do not introduce a refresh-rate cap or mesh combining until profiling shows a need. Union rebuild is synchronous once per settled altitude/revision; inspect the one-off build cost separately from steady-state flight.

## Offline verification

A Python translation of the sweep algorithm was compared to Shapely union on synthetic overlap, touching, containment, hole and sloped-edge examples and on the CL06B + 2 CL06C source recipes at Y0, Y30, Y78, Y110, Y145 (both possible X conventions at Y78). At cruise, 179 of 188 source rocks intersect the plane: 4,488 input contour segments, 1,362–1,398 emitted union edge segments, 1,362–1,398 fill triangles instead of about 9,100–9,400 original per-rock fill triangles. Numerical comparison passed area and boundary checks; counts are source-recipe estimates, not live Unity profiler results. C# compilation, actual imported mesh behavior, runtime performance and visual verification remain local.
