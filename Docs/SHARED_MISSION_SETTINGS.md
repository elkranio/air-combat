# Shared mission settings (DEV04)

Campaign missions M01–M03 must use the shared `PlayerLynx_Combat`, `ArcadeCameraRig`, `CombatHUD` and `CombatLightingRig` prefabs. Do not unpack them or add scene-local copies of common tuning. Scene references (player, camera, HUD, targets), operation bounds, mission-specific weapons and objectives remain scene-owned. Sandbox intentionally retains its diagonal camera yaw (-45 degrees) for existing comparison tests; campaign camera yaw is 0. Lighting is common: day, azimuth 52, elevation offset -10, shared URP pipeline. Lighting rig controls the actual light pose in Play; no placement changes to other objects are permitted.

- Player movement tuning lives in `FlightController` on the aircraft prefab (powered modes included); `Afterburner` owns fuel and boost settings. `FlightSession` binds systems, not movement stats.
- Engine clips and mix live in `Settings/Lynx_EngineAudio.asset`. The mission root's `Mission01EngineAudio` references the profile and its own phase context.
- Map refresh is `MissionAutoMap` for M01–M03. `TacticalMapView.Auto Bake Map` controls the editor-only pre-Play refresh. Missing or stale maps are baked using the existing geography pipeline; unchanged saved scenes reuse the asset. A dirty scene rebakes from its in-memory geometry. No automatic scene save. Manual baker remains available. The M01/M02 resolver uses their authored ground/airfield conventions; M03 has explicit ground and runway references.
- Cheats are independent scene overrides on the Lynx prefab, not shared balance settings.
- M03 **friendly runway heads northeast, world yaw 45 degrees**. Existing scene transforms (airfield, runway, player, camera, map geography) are authoritative. Never recreate an existing scene or rotate the base in a settings/terrain/map pass. The existing explicit Rotate Friendly Airfield command is a repair tool only. Its 45-degree target and the one-time foundation generator agree. Map refresh reads the pose, never writes it.
- `Air Combat > Missions > Audit Shared Settings (open scene)` reports common-reference drift and checks M03 runway heading without modifying anything. Verify each mission and Sandbox before committing. Any intended deviation belongs in the mission design, not an unnoticed prefab override.

DEV04 deliberately does not rewrite mission lifecycle/landing logic, change loadouts, rebalance weapons or move geography. M01/M02/M03 share the same currently authored takeoff, boundary and safety constants; the lifecycle-specific controller parameters are not migrated in this pass. Keep them unchanged until the common lifecycle is extracted. Re-bake maps once locally and commit the changed assets if desired. Confirm a second Play on a clean scene reuses its map.
